{{- /* Emits `og:image` and the Twitter card block. Hugo's `_internal/opengraph.html` handles everything else and is still called alongside this partial, but it emits no `og:image` when a page has no image of its own, which is exactly the gap the generated cards fill. So this adds one only when the embedded template did not. `_internal/twitter_cards.html` is deliberately NOT used. It always emits a `twitter:card`, and it says `summary` for a page with no authored image, with no way to override it short of emitting the tag twice. A `summary` next to a 1200x630 image is the same size mismatch decisions/page-metadata.md rejected the avatar fallback for, just inverted. Owning four lines buys an unambiguous answer. See decisions/og-images.md for why this narrows, rather than contradicts, the "use the embedded templates" decision. */ -}} {{- /* `_funcs/get-page-images` returns image objects, not URL strings, so the first one has to be dereferenced. Indexing is guarded because `index` on an empty slice is an error, not an empty value. */ -}} {{- $images := partial "_funcs/get-page-images" . -}} {{- $image := "" -}} {{- if gt (len $images) 0 -}} {{- $image = (index $images 0).Permalink -}} {{- end -}} {{- if not $image -}} {{- $image = partial "og/card-path" . | absURL -}} {{- end }} {{- /* Every page now carries a 1200x630 image, authored or generated, so the large card is always the honest claim. */}} {{- /* Matches the chain the embedded templates use, including the `.Summary` step that decisions/page-metadata.md rejects for `meta description`. Keeping it means this tag behaves the same as before for any page that loses its authored description. */}} {{- with or .Description .Summary site.Params.description | plainify | htmlUnescape }} {{- end }}
